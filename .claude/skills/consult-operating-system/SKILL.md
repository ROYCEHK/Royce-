## Engagement lifecycle
1. **Intake.** Problem-framing produces the Problem Statement and the key question. Open a row in the Engagement Register with these fields: ID, question, owner, decision-maker, deadline, status.
2. **Diagnose.** Run situation assessment and the assumption audit, then form the hypothesis tree. Each hypothesis needs an analysis that could prove it false.
3. **Analyse.** The practice partners run their skills against the hypotheses.
4. **Synthesise.** The narrative builder turns the findings into a pyramid storyline: answer first, supported by 3–5 arguments.
5. **Challenge.** The Engagement Sceptic attacks the storyline. Fix each objection or flag it.
6. **Decide.** Close with a decision memo, a roadmap and KPIs as needed.
7. **Close.** Add a lessons line to the Lessons Log, reusable artefacts to 60 Knowledge, and move the folder to 99.

## Thinking standards
- **MECE.** Break problems into mutually exclusive, collectively exhaustive buckets. State the logic of each split.
- **Hypothesis-driven.** Write the likely answer on day one and test it, rather than boiling the ocean.
- **80/20.** Find the few drivers that explain most of the value or risk.
- **So-what.** Every chart or table carries an action title, a full-sentence takeaway rather than a label.
- **Triangulate.** Back each important number with two independent methods or sources where possible.
- **Facts are facts.** Never invent data. Mark estimates as estimates and give the method. Turn missing data into an open question with an owner.

## Quality gate (before anything leaves the practice)
1. It answers the key question in the Problem Statement.
2. Every number traces to a named source with a date. Units, currency, period and FX are stated, and the totals tie.
3. Each external fact is linked and dated, and comes from public, lawful sources only.
4. The storyline passes the pyramid test: the answer stands up if the reader stops after the first line.
5. The Sceptic pass is done for high-stakes work: the 3–5 strongest objections, each answered.
6. OCSiAl investor-facing figures pass ocsial-disclosure-controller.
7. It is the right length for the audience: one page for a decision, a deck for a workshop.

## Standard output block (end of every deliverable)
`Answer` · `Key evidence` · `Sources` · `Assumptions & confidence (H/M/L)` · `Open questions (owner)` · `Recommended next step`
